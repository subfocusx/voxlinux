## 0. Решение по движку

**Выбран движок: sherpa-onnx, модель `gigaam-v3-e2e-rnnt-punct`**
(`sherpa-onnx-nemo-transducer-punct-giga-am-v3-russian-2025-12-16`).

| вариант | RTF | WER (вендор) | пунктуация | hotwords | вердикт |
|---|---|---|---|---|---|
| `gigaam-v3` (legacy, plain CTC) | 0.043 | 9.1 | нет | нет | оставить как fallback |
| `gigaam-v3-e2e-ctc-punct` | 0.042 | 12.0 | нативная | нет | быстрая альтернатива |
| **`gigaam-v3-e2e-rnnt-punct`** | **0.048** | **11.2** | **нативная** | нет | **основная** |
| `gigaam-v3-rnnt-plain` | 0.046 | 8.3 | нет | да | только если приоритет — hotwords |

Основание: у e2e-RNN-T ниже WER (11.2 против 12.0 у e2e-CTC) и выше F1
пунктуации (запятая 84.5 против 83.7, вопрос 79.8 против 78.6). Цена — +15 %
RTF, что при 10-секундной диктовке означает ~0.06 с.

Все модели выбираются через `config.json` → `{"model": "<id>"}`, переключение
без переустановки и без перезапуска.

## 6. Отклонено (с обоснованием)

- [x] **6.1** **Model-level hotwords** — отклонено: работают только с
      `from_transducer`, и только для char-level моделей. С punct-моделями (BPE)

      а `bpe_vocab` в официальном релизе нет. Итого: native-пунктуация **или**
      hotwords. Словарь терминов остаётся пост-хековым (`terms.py`).

      нет русского punctuator-модели, а нативная пунктуация уже есть в модели.
- [x] **6.3** **Переезд на onnx-asr** (ради «эталона» из 348★) — отклонено:

## Обоснование (краткое)

**Что было выдумкой в исходном аудите**

1. `feature_dim=80` — «баг». Не баг: sherpa-onnx перекрывает его на 64 для
   любой модели с метаданной `is_giga_am`
   (`csrc/offline-recognizer-ctc-impl.h:115`, то же в
   `offline-recognizer-transducer-nemo-impl.h:238`). Проверено: 40/64/80/128
   дают идентичный вывод. 80 — дефолт библиотеки, он же напечатан в
   официальных доках (откуда и ошибка).
2. «v3 = 64, v2 = 80» — у всех GigaAM эффективный 64.
3. «Консенсус-конфиг соседей» — в govorun-lite реально `featureDim = 80` для v3,
   `decoding_method` не задан, конфига v2 нет.
4. «Нужен внешний punctuator» — вместо него есть официальный `*-punct-*`.
5. «e2e = пунктуация внутри» — только для `-punct-` ассетов; обычный v3 rnnt —
   34 токена без пунктуации.
6. «giga-pisar кроссплатформенный» — только macOS.
7. «govorun-lite — Android на Kotlin» — мультиплатформа, основной язык Rust,
   sherpa-onnx только на Android.
8. «stt-ru — эталон e2e-интеграции» — стек onnx-asr, не sherpa-onnx.
9. «num_threads=2 достаточно» — нет: 1 → 1.38 с, 2 → 0.82, 4 → 0.52, 8 → 0.60.
10. «INT8/FP32/NNAPI» — Android-специфично, источников нет.

**Что подтвердилось**

- `model_type="nemo_transducer"` обязателен (дефолт Python — `"transducer"`).
- Silero VAD доступен и работает.
- Лимит 200 с — жёсткий: 199 с OK, 201 с → ошибка ONNX Runtime.
- WER 11.2 / 21.0 и F1 84.5 / 86.7 реальны, но это строка E2E RNN-T* вендорской
  таблицы (`salute-developers/GigaAM/evaluation.md`), а не измерения golos.

**Измеренные дефекты нашего кода (исправлены)**

- `scripts/test_transcribe.py:102` — `args.steps` → AttributeError на каждом
  запуске, тайминги не печатались.
- `voxapp/punctuation.py` — `add_punctuation` не считает запятую концом фразы →
  «…зеленый,.».
- `voxapp/engines.py:71,81` — `feature_dim=80` вводит в заблуждение.
- README/registry — «~163 MB» против фактических 155–162 МБ архива и ~224 МБ
  распакованного int8.
